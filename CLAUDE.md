Context for working on this repository. The owner is Francesco (GitHub `FRFAL99`); talk to him in Italian. Code, comments and commit messages stay in English.

## What this is

OneLM (called PrivateLM until the rename; package id `io.github.frfal99.onelm`, Dart package `onelm`): a Flutter app, forked from `orailnoor/cross-platform-llm-client`, with one purpose:

1. **Run a model on the phone**: GGUF via llama.cpp (`local_plugins/llama_flutter_android`), GPU offload (Vulkan), automatic settings from the device RAM.
2. **Run it across a cluster of phones** (`ClusterService`, llama.cpp RPC over the same Wi-Fi).
3. **Serve it** as an OpenAI-compatible API (`openai_server_service_io.dart`) so Francesco's own apps and scripts can use it: localhost by default, network mode requires an API key.

The chat screen exists to try the model. Anything else is out of scope (Francesco, 2026-11-20): no cloud providers, no features unrelated to running and serving the local model. Ask before adding something that doesn't serve these three points.

Everything runs on the user's devices. The only network calls are the ones the user starts: model downloads (Hugging Face), the manual update check (GitHub), and the cluster and server on the local network.

## Stack and layout

- Flutter 3.47.9 (pinned in CI; Flutter 3.50+ needs Gradle 9.3.1 and the Android project is on Gradle 8.14), Dart 3.13. State: GetX. Storage: Hive. HTTP: Dio + `package:http`.
- `lib/controllers` (GetX controllers), `lib/services` (inference, cluster, storage, download, server), `lib/views`, `lib/widgets`, `lib/core` (constants, routes, theme, UI kit), `lib/models`.
- Big screens and controllers are split with `part` files: `model_view.dart`, `chat_view.dart` and `model_controller.dart` keep the class, its state and `build`; each `*_<section>.dart` part holds an extension on that class (private for views, public `ModelDownloads`/`ModelLoading`/`ModelImport` for the controller, so callers keep writing `controller.loadModel(...)`) plus that section's private widgets. Class statics are not in scope inside extensions: make them top-level privates. Keep new code in the part it belongs to.
- **Navigation** (`HomeView`): four tabs, one per job: Home (`DashboardView`: model, server, cluster and speed cards, each with its next action; ⚙ opens Settings), Models (with Load settings: processor mode, context size, device info in `LoadSettingsView`), Server (examples come from `lib/services/server/api_examples.dart`, one topic × language at a time), Cluster. Tab indices are `AppTab`; `HomeController.openTab` closes pushed pages first. The chat is a test bench for the model, not a tab: it opens from Home (`AppRoutes.chat`), history is its end drawer, and `ChatController` is permanent so leaving the page keeps the conversation. Settings hold only generation defaults (system prompt, sampling, stop sequences), chat summaries, appearance and About.
- Platform splits use conditional imports (`*_native.dart` / `*_web.dart` / `*_stub.dart`).
- Native code lives in `local_plugins/llama_flutter_android` (llama.cpp, vendored and lightly patched for the phone cluster). It is large; don't touch it unless the task is about it.

## Rules and decisions

- **Name**: the app is OneLM. Internal identifiers keep the old name on purpose, because they are protocol or data: the cluster's mDNS type `_privatelm._tcp`, the pairing/crypto labels and `privatelm-*.h` files, wake-lock tags, the keystore alias `privatelm` and `PRIVATELM_ALLOW_DEBUG_RELEASE_SIGNING`. Third-party credits live in `THIRD_PARTY_NOTICES.md` and `lib/core/third_party_licenses.dart` (Settings › About › Open-source licenses): keep both in sync when a native component, font or bundled library changes, and give every catalogue model a `license`.
- **No cloud providers**: OpenAI, Anthropic, Gemini, OpenRouter and custom endpoints were removed (CloudService, cloud model picker, inference mode). Don't bring them back.
- **Secrets**: credentials never go in plain Hive. `HiveService.secretKeys` (today only the server API key) routes them to `flutter_secure_storage` (Keystore/Keychain); add any new credential setting to that set.
- **Updates**: in-app updates read GitHub Releases of `AppConstants.githubRepo`, which must point to this fork. The automatic check is off by default; the user checks manually.
- **No hidden network calls**: fonts (Inter, Fira Code) are bundled in `assets/fonts` (no `google_fonts`), PDF text uses `pdfrx` (PDFium) instead of Syncfusion, and the cluster pairs by IP (no camera/ML Kit QR scanner). Don't add analytics, crash reporting or packages that fetch at runtime.
- **Removed, don't bring back**: cloud providers, Task/ExecutionService (let the LLM run ADB shell commands), image generation (Stable Diffusion, Core ML, Stability AI), the LiteRT engine, Firebase/Crashlytics, the boot receiver, voice input (speech_to_text and the microphone permission), the chat-first home with greetings and prompt suggestions.
- One local engine only: llama.cpp with GGUF models.
- **CPU vs GPU**: llama.cpp's Vulkan backend is slower than the CPU on most phones (a Motorola measured 3.5 tok/s prompt, 8.3 generation on GPU), so the Auto processor mode uses the CPU and switches to the GPU only when speed tests of that model on this phone show the GPU faster (`autoUsesGpu`, `lib/services/processor_choice.dart`). CPU threads = one per performance core, efficiency cores (A53/A55/A510/A520) left out (`lib/services/cpu_threads.dart`, `DeviceInfoService.cpuThreads`).
- **Model downloads are verified**: `DownloadService.verifyDownload` hashes the finished file (`sha256OfFile`, in an isolate) and compares it with the catalogue's `sha256`/`mmproj_sha256`, else with Hugging Face's `X-Linked-Etag` (`ModelIntegrity`); a mismatch deletes the file. Every catalogue entry should pin its hashes: the `Model catalogue` workflow (runs on PRs touching `constants.dart`) checks them and prints the published hash of unpinned entries; `tool/pin_model_hashes.dart` writes them where Hugging Face is reachable.
- **System prompts**: the chat picks `uncensoredSystemPrompt` for models named uncensored/abliterated/dolphin; the API server never does (`forUncensored: false`): clients get the user's Settings prompt or the plain default whatever the file is called. Old default prompts in `legacySystemPrompts` count as the default.
- **Phone cluster** is core. Workers require a pairing code: a mutual HMAC-SHA256 challenge-response before the RPC HELLO (`ggml-rpc/privatelm-auth.h`, patched into Android's `ggml-rpc.cpp`); codes live in secure storage (`keyClusterWorkerCode`, `keyClusterPairingCodes`). Protocol "PLM2": ephemeral X25519 keys bound by the code's MACs, then every byte is a ChaCha20-Poly1305 record (`privatelm-crypto.h`, `socket_t::enable_encryption` in `transport.cpp`); "PLM1" workers are refused as an older version. Host tests: `scripts/rpc_crypto_test.cpp` (RFC vectors) and `scripts/rpc_pairing_test.cpp` (real master/worker, recording and tampering proxies). The master checks every worker with `LlamaCluster.checkWorker` before a load, because llama.cpp aborts on a failed connection. A worker that drops mid-generation no longer aborts the app: ggml-rpc logs "RPC worker lost", generation throws `CLUSTER_WORKER_LOST:<endpoint>`, `InferenceService` reloads the model without that worker and `generate` runs the request again once (`LostWorkerRetry`: transparent while nothing was streamed, otherwise only for callers that pass `onRestart`, like the chat). `unloadModel` only bumps `stopCount` when a generation was running, so the reload doesn't look like an interrupted answer. The iOS worker (`ios/llama_cpp_src`) is on an older llama.cpp (RPC v4) and has no pairing support.
- **Decisions** (`POST /v1/decisions`, `lib/services/decisions/`): typed answers (boolean, choice, score, numeric) with probabilities, without generating. Each question becomes a lettered multiple-choice prompt; native `LlamaTools.nativeScoreOptions` reads the evidence prefix once (reusing the KV cache), then each question's tail, and returns the answer letters' logits; Dart decodes them (softmax, abstention, uncertainty). Request/response follow Rizzo Flow's `/v1/decisions` (Apache-2.0, credited in `THIRD_PARTY_NOTICES.md` and the licenses page) so Francesco's `automazioni` scripts only change the URL. "Rizzo" never appears in names (third-party trademark). Qwen3 gets an empty think block (`LlamaTools.noThinkingPrefix`). Not done: calibration, the Jev-compatible `/v1/systemone`.
- **Chat storage**: messages live in a Hive `LazyBox` with a chatId → message ids index box; images are files under `chat_images/` (see `ChatImageStore`). Bump `HiveService._messageStorageVersion` and extend `_migrateMessages` when the layout changes.
- Removed features' Hive keys are deleted on startup (`HiveService._removedFeatureKeys`, `_removedSecretKeys`).
- New settings keys go in `AppConstants`. `HiveService.init` wipes unknown `server_*` keys: register new ones there.

## Working conventions

- Commits follow Conventional Commits with a scope, e.g. `feat(cluster): ...`, `fix(server): ...`, `chore: ...`.
- Work on a branch and open a PR against `main`; keep PRs focused.
- Run `flutter analyze` and `flutter test` before pushing. CI (`.github/workflows/android.yml`) runs only analyze and tests on PRs (about 3 minutes), so Kotlin and C++ are not compiled there: for a PR that changes native code, start the workflow by hand on the branch (workflow_dispatch builds APKs, signed with the release key when its secrets are set) before merging. Releases are one click: the `Release` workflow (workflow_dispatch) bumps `pubspec.yaml`, commits to `main`, tags `vX.Y.Z` and dispatches `android.yml` on the tag (a tag pushed with `GITHUB_TOKEN` triggers nothing), which publishes signed APKs to GitHub Releases. Signing needs the `ANDROID_KEY*` secrets, created once by Francesco with `scripts/create_release_key.sh`; manual branch builds use the same key when it is set, so they install over releases. Never replace that key. Tests live in `test/` and use Hive in a temp directory. Nobody has built the iOS/macOS apps since the cleanup: run `pod install` and an Xcode build before an iOS release.
